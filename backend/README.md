# 基于用户评论情感分析的商品个性化推荐系统

## 摘要

在电商平台中，用户面对大量同类商品时，常常很难在短时间内完成有效筛选。尤其是手机这类商品，品牌集中、型号繁多、价格跨度明显，单靠销量、均分或简单的关键字检索并不能充分反映商品是否真正符合用户需求。相比静态指标，用户评论中往往包含更直接的使用体验和情绪态度，这些内容如果能够被进一步处理并引入推荐环节，就能在一定程度上提高推荐结果的针对性。基于这一思路，本文结合当前项目实际实现内容，设计并完成了一个基于用户评论情感分析的商品个性化推荐系统。

系统采用前后端分离方式实现，后端以 Spring Boot 为核心框架，结合 MyBatis-Plus 和 MySQL 完成业务处理与数据存储。系统主要包含用户管理、商品管理、评论管理、行为记录、情感分析、个性化推荐和数据分析等模块。评论进入系统后，会先结合评分与评论文本进行情感判断，得到情感标签和情感得分，并同步更新对应商品的平均评分、评论数量和整体情感分值。在推荐部分，系统不再只依赖传统规则排序，而是引入基于项目的协同过滤思想，利用评论数据构建商品与用户之间的情感评分矩阵，计算商品之间的相似关系，再结合用户近期行为、品牌偏好和价格偏好生成推荐结果。当用户缺少有效历史行为时，系统再通过冷启动策略补足推荐列表。

除推荐功能外，系统还提供品牌情感分布、价格区间满意度、评论趋势分析和商品关联分析等接口，使评论文本、商品信息和用户行为之间能够形成较完整的数据闭环。从系统实现结果来看，该系统较好地展示了评论情感信息在推荐场景中的实际作用，也证明了 Item 协同过滤与情感分析结合用于商品推荐具有一定可行性和应用价值。

关键词：情感分析；个性化推荐；Item 协同过滤；用户评论；手机商品

## Abstract

In e-commerce platforms, users often face a large number of similar products, which makes product selection time-consuming and inefficient. This problem is more obvious in the mobile phone market, where products differ greatly in brand, model and price. Traditional recommendation methods based only on sales, average ratings or simple browsing records are often not enough to reflect users' actual preferences. In contrast, user reviews contain rich information about real experience and subjective attitude. If such information can be transformed into computable features and integrated into the recommendation process, recommendation results can become more targeted.

This paper designs and implements a personalized product recommendation system based on sentiment analysis of user reviews. The system adopts a front-end and back-end separated architecture. The back-end is implemented with Spring Boot, MyBatis-Plus and MySQL. It includes user management, product management, comment management, behavior recording, sentiment analysis, personalized recommendation and data analysis. After a review is submitted, the system combines the rating and textual content to generate a sentiment label and a sentiment score, and then updates the corresponding product statistics. In the recommendation module, an item-based collaborative filtering method is introduced. A product-user sentiment matrix is built from review data to measure product similarity, and the recommendation results are further refined by user behavior, brand preference and price preference. When a user has insufficient historical data, a cold-start strategy is used to complete the recommendation list.

The system also provides analytical interfaces such as brand sentiment distribution, price-range satisfaction, review trend analysis and product association analysis. The implementation shows that integrating sentiment analysis with item-based collaborative filtering can improve the expressiveness and practicality of recommendation results in product recommendation scenarios.

Key words: sentiment analysis; personalized recommendation; item-based collaborative filtering; user reviews; mobile phone products

## 第一章 绪论

### 1.1 研究背景

随着网络购物逐渐成为人们购买商品的常见方式，商品信息获取变得越来越方便，但选择难度也随之增加。用户在平台中看到的往往不是少量可直接比较的商品，而是成批出现的相似产品。平台通常会用销量、价格、评分和促销信息帮助用户缩小范围，不过这类信息更多反映的是商品整体表现，未必能准确贴合某个用户的真实关注点。很多用户在下单前仍然会专门去看评论，因为评论里包含了更具体的使用反馈，能够帮助他们判断这款商品到底好不好用，适不适合自己。

手机商品是一个很典型的场景。不同品牌之间有定位差异，同一品牌下又有大量不同价位和配置的机型，用户在选择时通常会把价格、性能、外观、续航、拍照和系统体验一起考虑。仅靠销量靠前或者评分较高，并不足以支撑用户完成判断。相比之下，评论文本往往更能体现使用者的真实态度。正向评论能够说明商品在某些方面表现较好，负向评论则可能暴露质量问题或体验缺陷。如果这些评论只是停留在展示层，没有进入推荐环节，那么平台就没有把最有价值的一部分数据真正利用起来。

当前不少推荐系统仍然更多依赖点击、浏览和评分记录，评论文本即使被保留下来，也常常只用于展示或者单独做情感分类，并没有与个性化推荐过程形成紧密结合。基于这一情况，本文尝试将评论情感分析与 Item 协同过滤结合起来，在商品推荐过程中进一步使用评论中蕴含的情绪信息和用户态度，使推荐结果不再只看表面热度，而是更重视商品口碑和用户偏好之间的关系。

### 1.2 研究目的与意义

本课题的主要目的，是构建一个能够把评论信息真正纳入推荐计算过程的商品个性化推荐系统，使评论不再只是静态文本，而是能够参与商品评价和推荐排序。系统通过对评论内容进行情感处理，将原本难以直接利用的自然语言信息转化为情感得分，再结合商品属性和用户行为完成推荐计算，这样能够在一定程度上提高推荐结果与用户需求之间的匹配程度。

从应用角度看，这种做法可以帮助用户更快地接触到评价较稳定、与其兴趣更接近的商品，降低在海量商品中反复筛选的时间成本。对于平台而言，情感分析结果和推荐结果还能为后台运营提供参考，使管理者能够观察品牌表现、价格区间反馈和评论趋势变化，不再只依赖销量榜单判断商品状态。

从研究角度看，本文的意义在于把评论情感分析、Item 协同过滤以及行为偏好补充策略放在同一系统中实现，形成从评论处理到推荐输出的完整流程。虽然系统没有采用特别复杂的深度学习模型，但它较清楚地展示了非结构化评论数据如何被转化为可计算指标，并进一步影响个性化推荐结果。

### 1.3 国内外研究现状

推荐系统的发展较早，传统方法主要包括基于内容的推荐、协同过滤推荐和混合推荐等。其中协同过滤方法因为不依赖对商品内容的深入理解，在很多场景下都具有较强适应性。基于用户的协同过滤强调寻找兴趣相近的用户，基于项目的协同过滤则强调寻找相似商品，并根据用户历史偏好进行推荐。后者在商品场景中应用较广，原因在于商品之间的关系往往更稳定，也更便于在系统中实现。

随着自然语言处理技术的发展，评论文本逐渐成为推荐研究中的重要信息来源。国外较早开始将情感分析、观点挖掘等方法引入推荐系统，希望借助评论中的语义信息弥补传统评分数据过于粗糙的问题。国内相关研究近些年也明显增多，尤其是在电商、外卖、旅游和影视等评论数据丰富的领域，越来越多研究关注文本情感对推荐效果的影响。

不过从很多实际项目和毕业设计情况来看，评论情感分析和推荐系统常常仍然是分离实现的。前者停留在正负面分类，后者继续依靠简单排序或基础行为统计，二者之间没有真正打通。本文在系统设计中尝试把评论情感得分直接用于商品统计、商品相似关系构建和推荐排序补充，使评论文本在推荐过程中发挥更直接的作用。

### 1.4 研究内容

本文围绕手机商品推荐场景展开，主要工作包括系统需求分析、数据库设计、评论情感分析流程设计、基于 Item 的协同过滤推荐实现、用户偏好补充策略设计、冷启动推荐设计以及后台数据分析接口实现。系统不仅返回推荐结果，还通过解释型接口给出推荐来源、得分构成和历史行为摘要，使推荐过程具有更强的可理解性。

### 1.5 论文结构

全文共分为六章。第一章主要介绍课题背景、研究意义和相关研究现状。第二章对系统需求进行分析。第三章给出系统总体设计和数据库设计。第四章重点说明系统各模块的实现方法，尤其是评论情感分析与 Item 协同过滤推荐逻辑。第五章介绍系统测试情况。第六章对全文进行总结，并说明后续优化方向。

## 第二章 系统需求分析

### 2.1 可行性分析

从技术角度来看，本系统采用的 Spring Boot、MyBatis-Plus 和 MySQL 均为较成熟的开发方案，开发文档充分，部署过程清晰，适合毕业设计规模下的项目实现。情感分析通过独立接口服务完成，后端只需要在评论保存时传入评分和评论内容即可获取情感结果，同时系统保留了情感服务异常时的评分兜底逻辑，这使整体流程更稳定。

从功能实现角度来看，Item 协同过滤并不要求特别复杂的数据结构，在当前项目中可以直接利用评论表中的商品编号、评论昵称和情感得分构建商品与用户矩阵，再通过余弦相似度计算商品之间的关联程度，这一实现路径与现有数据结构是兼容的。

从经济角度看，系统所依赖的软件环境均可在普通开发机器上部署运行，不需要额外购置大型服务器或专门设备，因此成本较低。对于毕业设计项目来说，这样的技术路线较为合适。

### 2.2 功能需求分析

系统面向普通用户和管理员两类角色。普通用户登录后可以浏览商品列表、按品牌和关键字检索商品、查看商品详情、查看评论信息、提交评论、记录点赞或浏览行为，并查看个性化推荐结果和推荐历史。为了让推荐结果更具解释性，系统还增加了推荐解释接口，用于返回推荐来源、推荐摘要和各候选商品的得分构成。

管理员主要用于维护平台数据和查看统计分析结果。管理员可以对商品和评论进行管理，也可以查看系统中商品总数、评论总数、用户数量和行为数量等基本统计信息，同时通过分析接口查看品牌情感分布、价格区间满意度、评论时间变化趋势以及商品之间的关联关系。

从业务流程来看，用户在浏览商品时会触发行为记录，评论提交后会触发情感分析和商品统计更新，这些数据变化又会进一步影响后续推荐结果。分析模块则负责把商品、评论和行为数据以可视化形式展示出来，使系统具备管理和展示双重作用。

### 2.3 非功能需求分析

在性能方面，系统需要保证商品分页查询、评论查询和推荐接口能够稳定响应。当前推荐逻辑需要遍历商品和评论构建矩阵并进行相似度计算，因此在数据量较小时可以满足需求，在更大规模数据下则需要继续优化。安全性方面，系统通过 JWT 完成登录后的身份验证，并依据角色进行权限区分。可维护性方面，系统采用控制层、服务层、实体层和数据访问层分层结构，不同模块职责较清楚，便于后续扩展。可理解性方面，新版系统加入了推荐解释返回结构，使推荐结果不只是一个列表，还能给出来源说明，这对系统展示和论文答辩都有帮助。

## 第三章 系统总体设计

### 3.1 系统架构设计

本系统采用前后端分离结构。前端主要负责页面交互和图表展示，后端负责业务逻辑、权限校验、推荐计算和数据访问。用户从前端发起请求后，请求进入后端控制器，由控制器调用相应服务层进行处理，最终通过 MyBatis-Plus 操作 MySQL 数据库。评论情感分析部分通过外部服务接口调用实现，后端在评论保存时向情感分析接口发送请求，并接收情感得分与标签。

后端系统运行在 `8080` 端口，情感分析服务配置在 `http://localhost:8000`。系统启动时会自动执行数据库初始化脚本，创建用户表、商品表、评论表和行为表，为后续业务提供基础环境。

### 3.2 系统模块设计

系统可以划分为用户认证模块、商品模块、评论模块、行为记录模块、推荐模块和分析模块。用户认证模块负责登录校验和身份识别。商品模块负责商品信息展示、品牌筛选和详情查询。评论模块负责评论分页、新增、修改和删除，并在评论保存时触发情感分析和商品统计更新。行为记录模块负责保存用户浏览、点赞和评论偏好动作。推荐模块负责基于用户历史行为和商品相似关系输出推荐结果。分析模块负责为后台和大屏展示统计数据。

### 3.3 数据库设计

系统数据库主要包含四张核心表。

`users` 表用于保存用户登录信息和角色信息，主要字段包括用户编号、用户名、密码、角色和创建时间。

`phones` 表用于保存商品数据，字段包括品牌、标题、当前价格、原价、优惠价、销量、店铺名称、图片地址、商品编号、链接地址、情感得分、平均评分和评论数量等。商品维度上的情感得分、评分和评论数量会随评论变化实时更新。

`comments` 表用于保存评论数据，主要字段包括商品编号、品牌、标题、评论用户昵称、评分、规格、评论时间、评论内容、情感得分和情感标签。该表既为情感分析提供原始文本，也为 Item 协同过滤提供用户与商品之间的情感评分依据。

`user_behavior` 表用于保存用户行为记录，字段包括用户编号、商品编号、行为类型和创建时间。行为类型包括浏览、点赞以及根据评论情感自动记录的偏好动作。

### 3.4 数据关系设计

在数据关系上，一个用户可以产生多条行为记录，也可以对多个商品发表评论；一个商品可以拥有多条评论，并对应多个行为记录。推荐模块虽然没有额外建立推荐结果表，但会读取评论表构建商品与用户之间的情感矩阵，再结合行为表中的近期记录进行推荐计算。这种设计结构相对简洁，能够满足当前项目的实现需求。

## 第四章 系统详细设计与实现

### 4.1 用户认证与权限控制实现

系统使用 JWT 作为身份认证方案。用户输入用户名和密码登录后，后端验证账号信息并生成令牌返回前端。后续请求由拦截器读取令牌中的用户编号和角色信息，写入上下文中供业务模块调用。普通用户可以浏览商品、提交评论、查看推荐结果和历史记录，管理员则可对商品和评论进行维护，并查看后台统计数据。

### 4.2 商品管理模块实现

商品模块支持分页查询、品牌筛选、关键字搜索、首页推荐展示和商品详情查看。商品详情接口除返回商品自身信息外，还会同时返回相关评论总数、情感标签分布和相似商品列表。如果当前访问者是已登录用户，系统在其进入详情页时会自动记录一条 `view` 行为，这为后续推荐模块收集用户兴趣提供了基础数据。

系统中的商品不仅保存基础字段，还保存评论相关统计信息。当评论数量变化时，商品表中的平均评分、评论数和情感得分都会被更新，因此商品数据不只是静态展示结果，而是会随着用户反馈持续变化。

### 4.3 评论管理与情感分析实现

评论模块支持分页查询、新增、修改和删除。用户提交评论后，系统会把评分和评论内容一起发送到情感分析服务，由服务返回情感得分和情感标签。情感得分用 0 到 1 的数值表示评论整体倾向，情感标签则分为正向、中性和负向。如果情感分析服务不可用，系统会根据评分结果给出兜底情感判断，避免评论流程中断。

评论保存成功后，系统会重新读取该商品下的全部评论，重新计算商品的评论数、平均评分和平均情感得分，并把结果写回商品表。这个过程保证了商品统计信息和评论数据之间的一致性。

在用户行为联动方面，如果当前评论由普通用户提交，系统会依据评论的情感标签自动写入行为记录。正向评论对应 `comment_positive`，中性评论对应 `comment_neutral`，负向评论对应 `comment_negative`。这样设计之后，评论本身不仅影响商品口碑，也会影响系统对用户偏好的判断。

### 4.4 用户行为记录实现

行为模块负责保存用户在平台中的主要交互动作，当前系统重点记录浏览、点赞和评论情感行为。每条行为记录都包含用户编号、商品编号、行为类型和创建时间。推荐模块读取的是用户最近一段时间内的行为，而不是全量历史，这样做的目的是更强调近期兴趣，避免过早以前的行为对当前推荐造成过强干扰。

系统同时提供历史记录接口，用于返回用户最近接触过的商品信息。这一部分既能增强前端展示，也便于验证推荐模块与行为模块之间的关联是否正常。

### 4.5 推荐算法总体设计

新版系统的推荐逻辑不再是单一路径，而是采用了三段式组合策略。第一步优先使用基于项目的协同过滤方法完成主推荐。第二步对协同过滤结果不足或排序需要补充时，引入基于品牌偏好和价格偏好的补充评分。第三步在用户历史记录过少或推荐数量仍不满足要求时，使用冷启动策略补齐结果。这样的设计兼顾了个性化程度、可实现性和稳定性。

从代码实现看，推荐服务会先读取用户最近 30 条行为记录。如果没有任何历史行为，则直接进入冷启动模式。如果存在历史行为，则读取全部商品和评论数据，并从评论表中提取商品编号、评论用户昵称和情感得分，用于构建商品与用户之间的稀疏矩阵。之后系统分别计算协同过滤推荐结果和偏好补充推荐结果，再进行合并；若数量仍不足，再加入冷启动候选结果补位。

### 4.6 基于 Item 的协同过滤实现

Item 协同过滤的核心思想，是根据商品之间的相似关系进行推荐，而不是先找相似用户。系统会把每个商品看成一个向量，向量维度由评论过该商品的用户构成，向量值则采用这些用户对该商品对应的情感得分。换句话说，若两个商品经常被相似用户评价，且这些用户给出的情感分值也较接近，那么这两个商品之间就更有可能存在相似性。

在实现中，系统首先根据评论表构建 `商品 -> 用户 -> 情感得分` 的映射矩阵。然后对于用户近期有过交互的商品，将其视为源商品，与其他候选商品逐一计算余弦相似度。若某个候选商品与多个历史商品都具有较高相似度，则该候选商品会得到更高的协同过滤得分。

为了使协同过滤结果更符合用户真实意图，系统并没有把所有历史商品一视同仁，而是根据行为类型给源商品分配不同权重。点赞行为权重最高，正向评论也会产生明显的正向加成，中性评论影响较弱，负向评论则会对相似商品形成抑制作用。这样一来，系统在做 Item 推荐时考虑的不只是“用户接触过什么”，还考虑了“用户对这些商品持什么态度”。

### 4.7 偏好补充与冷启动实现

单纯依赖 Item 协同过滤会遇到两个问题。一个问题是用户历史记录过少时，相似商品难以可靠计算；另一个问题是即使有协同过滤结果，也可能不足以覆盖需要返回的推荐数量。为了解决这些情况，系统增加了偏好补充策略和冷启动策略。

偏好补充策略主要从用户历史行为中提取两个特征。一是用户近期更常接触的品牌，系统会统计出现频次较高的品牌并视为偏好品牌；二是用户近期接触商品的平均价格区间，系统会把与该价格更接近的商品给予适当加分。在此基础上，再结合商品本身的情感得分、平均评分和评论数量，形成补充排序分值。这部分结果不依赖评论矩阵，因此能在协同过滤结果不足时起到稳定补位作用。

冷启动策略则主要面向没有历史行为的新用户，或推荐结果不足时的补全场景。系统根据商品自身质量信号进行排序，重点考虑商品情感得分、平均评分和评论数量，让口碑较好、评价较稳定的商品优先出现在推荐列表中。虽然这种方式个性化程度较弱，但它能保证系统在任何情况下都可以返回一个基本合理的结果集。

### 4.8 推荐解释机制实现

为了增强推荐结果的可理解性，系统新增了推荐解释接口。该接口返回的不只是推荐商品列表，还会说明推荐采用的主要策略、用户的历史来源商品，以及每个推荐项的总分、协同过滤得分、偏好补充得分和冷启动得分。对于由协同过滤产生的候选商品，系统还会返回其主要来源商品以及对应行为类型。

这一设计对于论文展示和系统答辩都很有帮助。它能够直观说明为什么某件商品会被推荐给当前用户，使推荐过程不再是一个完全黑盒的结果列表，而是可以被简单解释和观察的计算过程。

### 4.9 数据分析模块实现

分析模块主要用于展示评论和商品数据的统计结果。首页统计接口返回商品总数、评论总数和正向评论占比。后台统计接口返回商品数量、评论数量、用户数量、行为数量、品牌统计和最近评论内容。品牌情感分析接口用于展示不同品牌下正向、中性和负向评论的数量变化。价格区间满意度接口用于观察不同价格范围商品的情感得分和评价情况。月度趋势接口按评论时间统计评论数量和平均评分的变化，便于分析时间上的波动。关联分析部分则根据共同评论关系构建商品和品牌之间的联系，用于发现潜在的共同关注模式。

这些分析结果虽然不直接参与最终推荐排序，但它们为系统提供了补充价值，也有助于验证评论数据和商品数据之间是否存在清晰的规律。

## 第五章 系统测试

### 5.1 测试环境

系统测试环境为 Windows 平台，开发语言为 Java，JDK 版本为 17，后端框架采用 Spring Boot 3.3.5，数据库为 MySQL，数据访问采用 MyBatis-Plus。后端服务运行在 `8080` 端口，情感分析服务运行在 `8000` 端口。

### 5.2 功能测试

在登录测试中，输入正确用户名和密码后，系统能够成功返回 JWT 令牌，之后请求需要登录权限的接口时能够被正确识别，说明认证流程正常。

在商品模块测试中，商品列表分页、关键字搜索和品牌筛选均能正常返回数据，商品详情接口能够返回商品信息、评论数量、情感标签分布和相似商品列表，同时对已登录用户成功写入浏览行为记录。

在评论模块测试中，评论新增、修改和删除功能均可正常运行。评论提交后，系统能够生成对应情感得分和情感标签，并同步更新商品表中的平均评分、评论数量和情感得分。如果情感分析服务临时不可用，系统仍能根据评分完成兜底处理，保证评论流程不中断。

在推荐模块测试中，对没有历史行为的用户发起推荐请求，系统能够返回按情感得分、平均评分和评论数量排序的冷启动结果。对存在历史行为的用户发起推荐请求时，系统会先生成基于 Item 协同过滤的推荐，再通过偏好补充策略完成补足，最终得到完整推荐列表。推荐解释接口能够返回每个候选商品的推荐策略、总分构成和来源商品信息，说明推荐解释机制有效。

在分析模块测试中，首页统计、后台统计、品牌情感分析、价格区间满意度、评论趋势和关联分析接口均能正常返回数据，说明系统整体数据链路是完整的。

### 5.3 测试结果分析

测试结果表明，系统中的评论处理、商品统计、行为记录和推荐生成之间已经形成了较稳定的数据闭环。评论数据进入系统后，不仅能更新商品口碑信息，还能通过情感得分参与 Item 协同过滤矩阵构建。用户行为既影响源商品权重，也影响偏好补充部分的排序结果，这说明新版系统已经不再是简单的规则推荐。

不过系统仍然存在一些可以继续优化的地方。当前 Item 协同过滤是在服务层直接遍历评论矩阵和候选商品完成计算，当数据规模继续扩大时，推荐计算开销会明显增加。评论中的昵称被当作用户标识使用，这种做法在当前项目中可行，但在更真实的平台环境下还需要更严格的数据清洗与用户标识统一。除此之外，情感分析结果仍然受评论文本质量影响，当评论过短或表达模糊时，分类和得分可能存在偏差。

## 第六章 总结与展望

本文围绕手机商品场景，设计并实现了一个基于用户评论情感分析的商品个性化推荐系统。系统以评论数据、商品数据和用户行为数据为基础，将情感分析结果与 Item 协同过滤方法结合，并加入品牌偏好、价格偏好和冷启动补充机制，形成了较完整的推荐流程。与只依赖销量、评分或简单浏览记录的做法相比，本文实现的系统更重视评论中蕴含的真实情绪反馈，也更能体现用户近期兴趣对推荐结果的影响。

从工程实现上看，系统已经完成了用户登录、商品管理、评论管理、行为记录、推荐生成和数据分析等主要内容，并增加了推荐解释接口，使推荐结果具备一定可理解性。这种设计既符合毕业设计对系统完整性的要求，也使论文中的算法部分更容易结合实际代码进行说明。

后续如果继续完善，本系统仍有几条较明确的改进方向。情感分析部分可以引入更适合中文电商评论场景的模型，提高对细粒度情绪和隐含态度的识别能力。推荐算法可以进一步优化相似度计算与召回策略，在保留可解释性的前提下提升效率。用户行为类型也可以继续扩展，引入收藏、停留时长、加购和购买记录等更丰富的信号。如果这些内容继续补充，系统在推荐质量和研究深度方面都会得到进一步提升。
